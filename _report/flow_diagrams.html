핵심 포인트 · 코드 정합성 확인

  • OrderController 생성자: (Inventory, OrderQueue, PaymentController, InventoryController, MachineController) → 화살표 5개 모두 표시됨.
  • AdminController 도 findProductByName 을 위해 Inventory 직접 참조 — AC → INV 화살표.
  • OrderStatusView/AdminView 가 registerStatusView(this) 호출 — 양방향 점선이 아닌 실선/점선 두 개로 분리하여 정확히 표현.
  • 점선은 비동기(MakerThread → MachineController → broadcast).

핵심 포인트 · 코드 정합성 확인

  • findProductByName 은 inventory.listAll().values() 를 순회하며 name.equals() 비교. Map 키(ID) 조회와는 다른 경로.
  • processPaymentAndManufacture 내부에서도 다시 findProductByName 을 호출 — Controller 를 stateless 하게 유지하기 위함.
  • OrderQueue.enqueue 의 notifyAll() 이 dequeue 의 wait 에서 MakerThread 를 깨움. 두 스레드 사이의 유일한 경계.
  • MakerThread 의 알림은 한 주문당 정확히 2번: MAKING 진입 시 (onMakerEvent(order)) / 제조 완료 후 (onMakerEvent(null)).

핵심 포인트 · 코드 정합성 확인

  • cancelOrder 가 orderQueue.remove(order) 를 부르지 않으면, MakerThread 가 CANCELED 주문을 dequeue 한 뒤 setStatus(MAKING) 호출 시 OrderStatus.isValidTransition 이 false → IllegalStateException → 스레드 사망.
  • synchronized(order) 락은 "상태 확인 ↔ 변경" 사이를 보호. MakerThread 가 그 사이 MAKING 으로 못 바꾸게.
  • 재고 복구·broadcast 는 락 해제 후에 실행 — 락 보유 시간을 짧게.
